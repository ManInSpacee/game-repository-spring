# Game Library

REST API для учёта пройденных игр: добавление, просмотр, изменение и удаление игр
с проверкой бизнес-правил и единым форматом ошибок.

## Стек

Java 21, Spring Boot 4, Spring Data JPA (Hibernate), PostgreSQL 18, Docker, Bean Validation

## Запуск

```bash
docker compose up -d
```

Затем запустить `GameLibraryApplication`. API доступно на `http://localhost:8080`,
PostgreSQL — на порту `5438`.

## API

| Метод    | Путь          | Описание               | Успех | Ошибки        |
|----------|---------------|------------------------|-------|---------------|
| `GET`    | `/games`      | список игр             | 200   | —             |
| `GET`    | `/games/{id}` | игра по id             | 200   | 404           |
| `POST`   | `/games`      | добавить игру          | 201   | 400, 409      |
| `PUT`    | `/games/{id}` | изменить игру          | 200   | 400, 404, 409 |
| `DELETE` | `/games/{id}` | удалить игру           | 204   | 404           |

### Пример запроса

`POST /games`

```json
{
  "title": "Hollow Knight",
  "genre": "ADVENTURE",
  "releaseDate": "2017-02-24",
  "status": "COMPLETED",
  "completedAt": "2024-03-12",
  "rating": 10
}
```

`status` можно не передавать — по умолчанию `NOT_STARTED`.

### Формат ошибок

Ошибка бизнес-правила или «не найдено»:

```json
{ "error": "Игра с id 99 не найдена" }
```

Ошибка валидации полей:

```json
{
  "error": "Ошибка валидации",
  "fields": {
    "title": "must not be blank",
    "rating": "must be less than or equal to 10"
  }
}
```

| Статус | Когда                                                        |
|--------|--------------------------------------------------------------|
| 400    | не прошла валидация, нарушено бизнес-правило, некорректный JSON |
| 404    | игры с таким id нет                                          |
| 409    | игра с таким названием уже есть                              |

## Бизнес-правила

1. **Название уникально.** Повторное добавление той же игры → 409.
   При изменении название не считается занятым, если принадлежит самой редактируемой игре.
2. **Дату прохождения можно указать только у пройденной игры** (`COMPLETED`).
   Обратное не требуется: статус `COMPLETED` без даты допустим — пользователь может не помнить,
   когда прошёл игру.
3. **Дата прохождения не раньше даты выхода.**
4. Даты выхода и прохождения не могут быть в будущем, рейтинг — от 1 до 10.

Правила 1–3 проверяет сервис, правило 4 — Bean Validation на DTO запроса.

## Модель данных

Таблица `games`:

| Колонка        | Тип            | Ограничения                                      |
|----------------|----------------|--------------------------------------------------|
| `id`           | `bigint`       | первичный ключ, генерируется базой               |
| `title`        | `varchar(50)`  | обязательное, уникальное                         |
| `genre`        | `varchar`      | обязательное: `ACTION`, `RPG`, `STRATEGY`, `SHOOTER`, `ADVENTURE`, `PUZZLE`, `SIMULATION`, `OTHER` |
| `release_date` | `date`         | обязательное                                     |
| `game_status`  | `varchar`      | обязательное: `NOT_STARTED`, `IN_PROGRESS`, `COMPLETED` |
| `completed_at` | `date`         | необязательное                                   |
| `rating`       | `integer`      | необязательное, 1–10                             |
